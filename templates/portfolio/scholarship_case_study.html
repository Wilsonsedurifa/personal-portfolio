CASE STUDY / DJANGO

ScholarshipSystem

Scholarship management from intake to scholar lifecycle.

Our team built a Django staff portal that manages scholarship intake, examinations, document review, and scholar records, with concurrency-safe slot allocation by municipality and education level.

Source code is private because this is a government system. Details are shared with permission.

01 / CONTEXT

The problem

Scholarship opportunities are limited and distributed per municipality and education level. Intake, review, examinations, and document checks involve many steps and staff members, so the process needs strict capacity control, clear status tracking, and an audit trail. 02 / APPROACH

The solution

Our team built a Django web system for application intake, admissions review, examination scheduling with QR-based check-in, document verification, and scholar management including renewals, profile updates, and announcements. Staff roles and permissions are configurable at a granular level.

03 / CAPACITY

How slot management works

  • Capacity is defined per semester, municipality, and education level, with separate public/private-school pools where needed.
  • Staff allocate slots through a preview-and-confirm flow that detects stale previews before saving.
  • A slot is reserved only when staff mark an applicant eligible for examination, so capacity reflects real progress.
  • Reservations use transactions, row locking, and conditional updates to prevent over-allocation when reviewers work at the same time.
  • Capacity cannot be reduced below what is already used, and duplicate pools are blocked at the database level.
  • If a pool is full, the applicant is routed to a slots-full outcome.
  • Every capacity or publication change creates an auditable operation record.

04 / ENGINEERING

Key technical decisions

  • Append-only status history supports a full audit trail, and the workflow allows only valid status transitions.
  • Category-level publication controls are separate from capacity configuration.
  • Academic-year validation allows one active year and prevents overlapping periods.
  • A versioned dynamic form builder supports controlled changes to application data collection.
  • An automated test suite includes more than 300 tests.
