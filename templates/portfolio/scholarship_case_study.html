CASE STUDY / DJANGO · POSTGRESQL

ScholarshipSystem

Province-wide scholarship management from intake to scholar lifecycle.

Built for the Provincial Government of Bulacan, this Django staff portal manages scholarship intake, batch slot allocation, QR-verified examinations, OCR document checks, and scholar records across all districts and municipalities.

Source code is private because this is a government system. Architecture details and interactive simulations are shared with permission.

01 / CONTEXT

The problem

Scholarship opportunities are limited and distributed across all districts, municipalities, and education levels in Bulacan. Previously, tracking slots and applicant requirements relied on manual, spreadsheet-based processes — leading to repeated encoding, hard-to-verify capacities across municipalities, and delayed status updates when multiple staff members reviewed applications at the same time.

02 / APPROACH

The solution

Our team built a Django web system backed by PostgreSQL for application intake, admissions review, examination scheduling with QR code generation and a built-in QR scanner, OCR-assisted document verification, and scholar lifecycle management including renewals, profile updates, and announcements. An AI chatbot powered by the Hugging Face API and deployed via Telegram also lets applicants get direct assistance, while staff roles and permissions remain configurable at a granular level.

03 / CAPACITY

How slot management works

  • Capacity is defined per semester, district, municipality, and education level (Junior High, Senior High, Masteral, Board Review), with separate public/private-school or single-pool modes.
  • Staff stage batch allocations across multiple districts and municipalities in a save-preview queue that detects stale previews before committing to PostgreSQL.
  • A slot is reserved only when staff mark an applicant eligible for examination, so capacity reflects real progress.
  • Reservations use database transactions, row locking (select_for_update()), and conditional updates to prevent over-allocation when reviewers work concurrently.
  • Capacity cannot be reduced below what is already used, and duplicate pools are blocked at the database level.
  • If a pool is full, the applicant is automatically routed to a slots-full outcome, and every capacity or publication change creates an auditable operation record.

04 / ENGINEERING

Key technical decisions

  • Append-only status history supports a full audit trail, and the workflow allows only valid status transitions.
  • Scheduled publication controls (Not scheduled, Scheduled, Published, Paused) are decoupled from capacity configuration with full change history.
  • Academic-year validation enforces one active year at a time and prevents overlapping periods.
  • A versioned dynamic form builder supports controlled changes to application data collection without code edits.
  • An automated test suite includes more than 300 tests covering slot locking, workflows, and permissions.

09 / OUTCOME

Operational impact

Replaced fragmented, spreadsheet-based tracking with a single auditable platform across Bulacan’s districts and municipalities — turning multi-step manual checks into a fast, concurrency-safe staff workflow.

BEFORE

Manual & fragmented

  • Spreadsheet-based slot tracking with manual cross-checking per municipality.
  • One-at-a-time capacity edits and delayed visibility into remaining slots.
  • Manual paper/file verification and repetitive applicant inquiries.
AFTER

Structured & auditable

  • Batch allocation save-preview across districts in a single pass with row-locked reservations.
  • Scheduled publication states and append-only audit logs for every status change.
  • Single-scan QR check-in, OCR document validation, and 24/7 Telegram chatbot assistance.
